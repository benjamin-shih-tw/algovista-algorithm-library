# Stage 1 — Animation Structural Audit Baseline

Baseline branch: `baseline/pre-animation-rework-2026-10-01`  
Baseline UI commit: `039d02eafc450854c63d09ec02d73d364a500b9b`  
Audit implementation head: `76ea81838ef47dcb168f7b1b999e2651f9a4d6c3`

> This is a structural diagnostic, not a human semantic quality grade. A repeated state can occasionally be intentional; the purpose is to identify where human review and execution-trace reconstruction should start.

## 1. Scope

The Stage 1 scanner evaluates all 202 lessons after the current enrichment pipeline and compares them with their raw source lessons.

It records:

- source family
- whether the lesson was originally authored as `animationVersion: 2`
- whether it passes through `expandGuidedFrames()`
- raw frame count and final frame count
- meaningful C++ line mapping coverage
- adjacent algorithm-data state changes
- adjacent rendered-state changes
- focus-only transitions
- code-only transitions
- generic generated step wording
- completion-factory generic focus usage
- structural risk flags

The repeatable command is:

```bash
npm run audit:animation:stage1
```

It generates:

- `.tmp/stage1-animation-audit.json`
- `.tmp/stage1-animation-audit.md`

and prints the summary to CI logs.

## 8. Root-cause diagnosis from Stage 1

The current pipeline is:

```text
raw lesson
  ↓
ensureGuidedLesson()
  ↓
expandGuidedFrames() for 186 lessons
  ↓
enrichLesson()
  ↓
enrichPedagogy()
  ↓
ensureCodeCoverage()
  ↓
buildVisualTrace()
  ↓
UI
```

For generic-expanded lessons, frame count is currently driven largely by meaningful code-line count:

```ts
total = Math.min(20, Math.max(10, meaningful.length))
```

The system then distributes a much smaller number of raw semantic phases across those generated steps.

That architecture explains the Stage 1 measurements:

1. one semantic state is repeated over several generated frames;
2. different C++ lines are assigned to those repeated states;
3. generic prose is generated to make each repeated frame look like a distinct teaching step;
4. animation count and code coverage appear complete even when execution state has not actually advanced.

The completion-factory group amplifies this effect because 111 lessons begin from only three conceptual frames.

## 9. Stage 1 conclusion

The main problem is **not insufficient UI information** and is no longer primarily a page-layout problem.

The main structural issue is:

> **the system generates animation steps from code-line distribution and conceptual phases instead of generating code highlights and explanations from real execution events.**

This gives the next stages a clear target.

Stage 2 should now perform human semantic review of representative lessons and verify exactly what state/event each algorithm truly requires before any mass rewrite begins.

## 10. Regression targets

These Stage 1 measurements become the baseline for later work.

Desired direction:

- generic-expanded lesson count: **186 → 0 or explicitly justified exceptions**
- generic generated text: **89.1% → near 0%**
- data no-op transitions: **69.6% → only intentional explanatory pauses**
- code-only transitions: **42.3% → near 0%**
- completion lessons using generic focus: **108 → 0**
- meaningful C++ coverage: **remain at 100%**
- authored-v2 regressions: **0 new regressions**

No later optimization should improve the visual metrics by reducing meaningful C++ coverage or hiding necessary execution states.
